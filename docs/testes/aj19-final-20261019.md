## 1. Migração proposta (ficheiro a criar em `drizzle/migrations/`, NÃO aplicada)

Coordenada com a proposta choice ainda inerte (`docs/testes/smart-link-choice-ios/choice-arrival.PROPOSTA.sql`): a coluna `arrival_event_id` e o índice por (link, chegada, destino) são pré-requisito partilhado; esta migração inclui-os com `IF NOT EXISTS` para ser aplicável em qualquer ordem.

```sql
-- AJ19+AJ14 opção A. PREPARADO, NÃO APLICADO. Aplicação futura só pelo canal oficial
-- de migrações, após o Pedro colar este DDL e o volume semanal no quadro.
-- Um bloco, uma transação; só aditivo (ADD COLUMN IF NOT EXISTS, CREATE ... IF NOT EXISTS,
-- DROP/ADD só da CHECK de 'event', sem tocar em linhas).
SET lock_timeout = '5s';

-- 1a. Guarda: a claim canónica tem de estar no estado conhecido.
DO $$ BEGIN
  IF md5(pg_get_functiondef('public.song_link_event_claim(jsonb)'::regprocedure))
     <> '0fa7ff7255cf58ace770d21abfabe2e1' THEN
    RAISE EXCEPTION 'canonical claim source changed' USING ERRCODE='55000';
  END IF;
END $$;

-- 1b. CHECK de event alargada (só a check; nenhuma linha é lida para escrita nem alterada).
ALTER TABLE public.song_link_events DROP CONSTRAINT song_link_events_event_check;
ALTER TABLE public.song_link_events ADD CONSTRAINT song_link_events_event_check
  CHECK (event IN ('arrival','choice','app_open'));

-- 1c. Vínculo choice/app_open à chegada (partilhado com a proposta choice; idempotente).
ALTER TABLE public.song_link_events ADD COLUMN IF NOT EXISTS arrival_event_id text;
ALTER TABLE public.song_link_events DROP CONSTRAINT IF EXISTS song_link_choice_arrival_check;
ALTER TABLE public.song_link_events ADD CONSTRAINT song_link_choice_arrival_check
  CHECK (arrival_event_id IS NULL OR (event IN ('choice','app_open') AND destination IS NOT NULL
  AND arrival_event_id ~* '^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$'));
CREATE UNIQUE INDEX IF NOT EXISTS song_link_choice_arrival_destination_uidx
  ON public.song_link_events(link_id, arrival_event_id, destination)
  WHERE event='choice' AND arrival_event_id IS NOT NULL;
-- Máximo um app_open por chegada (registo; a entrega é controlada pelos slots abaixo).
CREATE UNIQUE INDEX IF NOT EXISTS song_link_app_open_arrival_uidx
  ON public.song_link_events(arrival_event_id)
  WHERE event='app_open' AND arrival_event_id IS NOT NULL;

-- 1d. Slots de entrega por (chegada, fornecedor, evento): reserva atómica antes da entrega.
-- Uma única ListenClick Meta por chegada, partilhada entre choice e app_open
-- (event_id canónico arrival_event_id || ':open'); uma única CompleteRegistration
-- TikTok por chegada, só no app_open.
CREATE TABLE IF NOT EXISTS public.song_link_delivery_slots (
  arrival_event_id text NOT NULL,
  provider text NOT NULL CHECK (provider IN ('meta','tiktok')),
  event_name text NOT NULL CHECK (event_name IN ('ListenClick','CompleteRegistration')),
  status text NOT NULL DEFAULT 'reserved' CHECK (status IN ('reserved','delivered','failed','unknown')),
  reserved_by uuid,          -- id da linha song_link_events que ganhou o slot
  reserved_at timestamptz NOT NULL DEFAULT now(),
  delivered_at timestamptz,
  PRIMARY KEY (arrival_event_id, provider, event_name),
  CHECK (arrival_event_id ~* '^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$')
);
-- Sem GRANT a anon/authenticated (mesmo padrão de song_link_events): só service_role.
ALTER TABLE public.song_link_delivery_slots ENABLE ROW LEVEL SECURITY;
-- 0 policies: fechada à Data API; a edge function acede com service_role (bypass RLS).

-- 1e. Índices de apoio à deduplicação do ViewContent (secção 3).
CREATE INDEX IF NOT EXISTS song_link_arrival_fbclid_idx
  ON public.song_link_events(link_id, fbclid, created_at)
  WHERE event='arrival' AND fbclid IS NOT NULL;
CREATE INDEX IF NOT EXISTS song_link_arrival_ttclid_idx
  ON public.song_link_events(link_id, ttclid, created_at)
  WHERE event='arrival' AND ttclid IS NOT NULL;
```

Verificação pós-aplicação (obrigatória pelas condições do interruptor): `pg_get_constraintdef` da check, `pg_get_indexdef` dos 4 índices, definição e ACL de `song_link_delivery_slots` (RLS=true, 0 policies, sem grants a anon/authenticated), e `song_link_events` sem nenhuma linha alterada (count antes = count depois).

## 2. Diff proposto da `song-link-event` (resumo; diff completo após OK)

1. Aceitar `event='app_open'` além de arrival/choice; validações: `arrival_event_id` UUID obrigatório, `destination` obrigatório e configurado no link, `opened='app'`, `mode` informativo, `elapsed_ms` 0–6000, chegada SSR real do mesmo link/empresa, não futura, < 2 h (mesmas regras da proposta choice). Respostas: 200 ok / 200 duplicate / 400 payload inválido / 403 origem ou chegada inválida / 404 link / 429 limite / 500 interno.
2. Reserva atómica antes de qualquer entrega: `INSERT INTO song_link_delivery_slots ... ON CONFLICT DO NOTHING RETURNING arrival_event_id` sob lock da linha da chegada. Quem não ganha o slot não entrega, mas o registo app_open fica gravado.
3. Meta: `ListenClick` na choice elegível e no app_open, sempre com `event_id = arrival_event_id + ':open'` e slot (`meta`,`ListenClick`). Nunca ListenOpen.
4. TikTok: `CompleteRegistration` só no app_open, `event_id = arrival_event_id + ':open'`, slot (`tiktok`,`CompleteRegistration`). ClickButton da choice fica igual (UUID próprio da choice).
5. ViewContent da chegada: inalterado (nome, ID, enrichment, entrega), exceto a deduplicação da secção 3.
6. Falha/resultado desconhecido na entrega: slot fica `failed`/`unknown` com o mesmo ID; nunca ID novo nem reenvio cego. Perder o slot Meta não suprime o registo app_open nem o CompleteRegistration TikTok.

## 3. Deduplicação do ViewContent (NOVO)

Facto: a 19/10, no Android Meta, 17,5% das chegadas eram repetidas (373 visitantes com >1 chegada, 223 em <10 s). Hoje cada repetição gera ViewContent CAPI/TikTok com event_id próprio.

Proposta: a chegada é sempre gravada. Antes da entrega do ViewContent, o servidor procura outra chegada do mesmo link com o mesmo fbclid (Meta) ou ttclid (TikTok) nos últimos 30 min:

- Se existir, não envia ViewContent a esse fornecedor e marca o status dessa linha como `'duplicate'` (valor novo em `capi_status`/`tiktok_status`; sem CHECK nessas colunas, não precisa de DDL de constraint).
- A marcação é por fornecedor: uma chegada pode ser `duplicate` na Meta e `enviado` no TikTok.
- A janela de 30 min conta da chegada anterior mais recente com a mesma chave (lag), não da primeira.

DDL necessário: só os dois índices parciais 1e (lookup por (link, fbclid/ttclid, created_at)). Sem índice, a procura varreria as chegadas recentes do link a cada pedido.

## 4. Contrato para o Portal (app_open) — a levar ao agente do Portal

O Portal tem o commit d67e43a por publicar (`opened:'app'` no SSR e diag hidden/pagehide `android_after_inline`). Em cima disso:

- Armar o detector enquanto a página está visible, antes do redirect Android (android_inline/android_intent/retry) ou no primeiro toque iOS dirigido à abertura da app.
- No `visibilitychange` para hidden, se 0 <= decorrido <= 6000 ms, enviar UMA vez por chegada via `sendBeacon` com `Blob text/plain;charset=UTF-8` para `POST <erp>/functions/v1/song-link-event`.
- Não disparar se a página já estava hidden ao armar, por pagehide isolado, toque "outro", destino Instagram/seguir artista ou botão web. Um retry Android pode rearmar a janela, nunca um segundo envio.
- Corpo (JSON no blob):

  {"event":"app_open","slug":"<slug>","arrival_event_id":"<uuid da chegada SSR>","event_id":"<arrival_event_id>:open","destination":"spotify","opened":"app","mode":"android_intent|android_inline|android_retry|ios_tap","elapsed_ms":850,"page_url":"https://www.mundopropicio.com/m/<slug>"}

- Encaminhar ttclid/ttp e identificadores Meta disponíveis e permitidos pelo consentimento; não inventar cookies nem guardar IP. `ttp` não está persistido: tem de acompanhar o pedido quando disponível.
- Identidade/empresa/UTMs vêm do link e da chegada resolvidos no servidor; o Portal nunca escreve diretamente na tabela.
- Beacon não expõe a resposta; 200 ok = persistido/agendado, não prova de entrega às APIs. Prova por leitura dos registos/status e códigos de teste.
- Pixel browser Meta: trava local por chegada, sempre ListenClick com o mesmo ID canónico `arrival_event_id + ':open'`; não atrasar o beacon à espera do pixel.
